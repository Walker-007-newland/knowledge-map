# AI 路线节点编写说明（给写内容的代理）

先读 `docs/ai-roadmap.md`（路线、节点清单、链接白名单），再读 `docs/AUTHORING.md`（题型、选项打乱、样式），照着 `www/data/dist.js` 的写法和深度来写。

## 和软考知识点的区别
- 这是**学技能**，不是背考点：讲清“是什么 → 为什么 → 怎么做 → 常见坑”，多给能直接照做的步骤和小例子（短代码片段可以用 `<pre><code>…</code></pre>`，每段不超过 15 行，手机上能看）。
- 讲解厂商中立：用“大模型 API”“编程助手”这类通称，举例时可以提具体产品名，但**不写版本号、价格、榜单、参数规模、发布日期**这类会过时的数字。
- 只写稳定、确定的知识。拿不准的不写。

## 字段
```js
RK.ai.nodes.push({
  id: 'ai-xxx', stage: 'ai4', title: '…', short: '≤ 8 字',
  keywords: '搜索用',
  prereqs: ['ai-…'],            // 只能指向 ai-roadmap.md 里的 id
  tip: '一句话：这一节最重要的是什么',
  learn: [{ h, html }],          // 2～4 小节，样式同 AUTHORING（key / warn / tbl，表格最多 3 列）
  examples: [...], tests: [...], // 题型同 AUTHORING；以单选为主，可少量 fill / num
  handson: ['动手任务 html', …],   // 2～4 条，电脑上 10～60 分钟能做完的小练习，写清做什么、做到什么程度算完成
  links: [{ t: '标题', url: '…' }] // 0～3 条，只能用 ai-roadmap.md 白名单里的地址
});
```
- 题量：每个 learn 小节至少 1 道例题、2 道测试题；一般每节点 2～3 道例题、6～9 道测试题。题目考理解和判断（场景题：“这种情况该怎么做”），不考死记。
- 选项会被打乱：解析里不写“选 A / 第二项”；每题只有一个正确答案；answer 可以都写 0；不要“以上都对”。
- 计算题（如精确率、召回率、F1、token 估算）用 python 验算。
- 模板字符串里不要出现未转义的反引号或 `${`；代码片段里的 `<` `>` `&` 要写成 `&lt;` `&gt;` `&amp;`。

## 文件与自检
- 只写分给你的文件，开头一行注释。index.html 已经引用好了。
- 本机没有 node。预览服务 http://localhost:8805（根目录 ruankao-app），`/docs/check.html` 会检查 AI 节点的格式（别人的文件可能还没写好，只看你的 id）。也可以在页面里用 `new Function` 执行你的文件试试。
