# 内容编写说明（给写内容的代理）

读者：在职成人，备考软考高级「系统架构设计师」（2027 年 5 月），在**手机竖屏**上看。

## 先读
- `docs/AUTHORING.md`：字段、题型、版权、样式规范，必须遵守
- `docs/phase3-6-spec.md`：清单和 id（只写分给你的组）
- 照着写的样板：`www/data/samples.js`（已审核），以及 `www/data/quality.js`、`www/data/design.js`（已审校通过）

## 知识点要求
- 口径以《系统架构设计师教程（第 2 版）》和考试大纲的常见说法为准。教材说法不一的地方，用软考最常见的口径，并在讲解里用一句话点出。**不确定的事实不要写，宁缺毋滥。**
- 手机阅读：表格最多 3 列，段落短；多用 `<div class="key">` 总结、`<p class="warn">` 写易错点；每个点 2～3 个 learn 小节；不要放大图。
- 题量按要点覆盖：每个小节至少 1 道例题、至少 2 道测试题，高频点 3 道。一般每点 2～3 道例题、6～10 道测试题。以单选为主（模拟卷只抽单选），可以少量 fill / num。
- 计算题要写出完整算式，数值自己用 python 验算；num 题写 unit，需要时写 tol（如 0.005）。
- 选项会被程序打乱：解析里不能写“选 A”“第二项”；干扰项要像真考那样似是而非；每题只有一个正确答案；`answer` 是正确选项下标，可以都写 0；不要“以上都对”。
- 题目全部原创，不抄真题原文和教程原文。
- freq 按近年考频估 1–3；tip 一句话写怎么考。prereqs 只能指向已有的或清单里的 id。

## 案例题要求（cases2.js / cases3.js）
- 字段见 AUTHORING.md。每道案例 3 小问，points 合计 **正好 25 分**；`required` 只有质量属性 / 架构评估类写 true。
- 情境原创、行业多样（政务、医疗、制造、金融、物流、教育……），不用真实公司名。
- 题型仿真考：选型并说明理由、补全图表 / 填空、分析问题给方案、比较两种方案。参考答案写得像高分答案；评分要点能逐条判断“答到 / 没答到”，每条 1～4 分，写清关键词。
- `nodes` 写相关知识点 id。

## 论文要求（essays2.js）
- 格式同 `www/data/essays.js` 里的 `e-eval`；`rubric: RK.essayRubric, checklist: RK.essayCheck`（已是全局变量）。
- prompt：先一段背景（150～250 字），再“请围绕‘论××’论题，依次从以下三个方面进行论述”+ 三问；第 1 问固定是“概要叙述你参与管理和开发的软件项目以及你在其中所承担的主要工作”。
- guide：结构与字数表、第 2 / 3 问可以怎么组织（给出 3～4 个可写的分论点和每段写法）、该论题常见扣分点、摘要示例结构（用 20×× 和 ×× 占位，不写真实项目）。

## 文件
- 文件开头一行注释说明内容。知识点用 `RK.nodes.push({...}, ...);`，案例 `RK.cases.push(...)`，论文 `RK.essays.push(...)`。
- **只写分给你的文件**，不要改其他文件（index.html 已经引用好了）。
- 模板字符串里不要出现未转义的反引号或 `${`。
