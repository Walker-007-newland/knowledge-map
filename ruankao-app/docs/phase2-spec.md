# 第 2 阶段：架构核心（软件架构 / 质量属性与评估 / 系统设计与设计模式）

已有样板：`a-style`（架构风格五大类）、`q-attr`（质量属性与场景）、`q-atam`（ATAM）。新点不要重复这三个点已讲的内容，需要时用 `prereqs` 指过去。

## 组 1：`www/data/arch.js`（module: `arch`，id 前缀 `a-`）

| id | 标题 | 要点 |
|---|---|---|
| a-concept | 软件架构的概念与作用 | 定义（构件、连接件、约束）；架构在需求与设计之间的作用；架构的重要性（沟通、早期决策、可复用抽象）；架构设计与生命周期 |
| a-41view | “4+1”视图模型 | 逻辑、开发、进程、物理视图 + 场景；各视图面向谁、关注什么、用什么图 |
| a-adl | 架构描述语言 ADL | 构件、连接件、架构配置三要素；常见 ADL；ADL 与 UML 的关系 |
| a-style2 | 其他架构风格 | C2 风格（规则）、过程控制（闭环）、异构风格；REST 风格的约束 |
| a-mvc | MVC / MVP / MVVM | 三者分工与区别，各自适用场景 |
| a-cs | C/S、B/S 与多层架构 | 两层 C/S 的问题、三层 C/S、B/S、混合架构；各自优缺点 |
| a-dssa | 特定领域软件架构 DSSA | 定义；基本活动（领域分析、领域设计、领域实现）；参与人员角色；三层次系统模型 |
| a-absd | 基于架构的软件设计 ABSD | 三个基础；六个子过程（需求、设计、文档化、复审、实现、演化）；视角与视图、用例与质量场景 |
| a-component | 构件与构件组装 | 构件特征；构件模型与主流规范（EJB/COM+/CORBA/.NET）；构件获取与组装方式；接口 |
| a-soa | SOA 与 Web 服务 | SOA 概念与原则；Web Service（SOAP、WSDL、UDDI）；ESB 作用；SOA 与微服务的区别（简述，微服务细节在第 4 阶段） |
| a-product | 软件复用与产品线 | 复用的对象与层次；产品线（核心资产、建立方式：演化/革命 × 现有/全新产品线） |
| a-evolve | 软件架构演化 | 演化的类型与原则；静态演化与动态演化；架构维护 |
| a-mda | 模型驱动架构 MDA | CIM / PIM / PSM 与模型转换；与传统开发比较 |

## 组 2：`www/data/quality.js`（module: `quality`，id 前缀 `q-`）

| id | 标题 | 要点 |
|---|---|---|
| q-model | 软件质量模型 | ISO/IEC 9126 六大特性及子特性；ISO/IEC 25010 的变化；McCall 模型简述 |
| q-reliab | 可靠性指标与计算 | MTTF、MTTR、MTBF、可用度；串联、并联、混联系统可靠度计算 |
| q-faulttol | 容错与可靠性设计 | N 版本程序设计、恢复块、防卫式程序设计；双机热备 / 冷备 / 双机互备；故障检测与恢复 |
| q-perf | 性能评估 | 性能指标（响应时间、吞吐量、资源利用率、并发）；基准测试与常用方法；阿姆达尔定律；性能测试类型（负载、压力、容量） |
| q-evalmeth | 架构评估方式与 SAAM | 三类评估方式比较；SAAM 的步骤与输入输出；评估参与者 |
| q-tree | 效用树与质量属性场景实战 | 效用树的构成与填写；把描述改写成六要素场景；案例题常见空的填法 |

## 组 3：`www/data/design.js`（module: `design`，id 前缀 `ds-`）

| id | 标题 | 要点 |
|---|---|---|
| ds-oo | 面向对象基础 | 对象、类、封装、继承、多态、消息；类之间的关系（依赖、关联、聚合、组合、泛化、实现）及 UML 表示 |
| ds-principle | 面向对象设计原则 | 单一职责、开闭、里氏替换、依赖倒置、接口隔离、迪米特、合成复用 |
| ds-uml-static | UML 结构图 | 类图、对象图、构件图、部署图、包图；用例图与 include / extend / 泛化 |
| ds-uml-dyn | UML 行为图 | 顺序图、通信图、状态图、活动图（泳道、分叉汇合）；顺序图与通信图的区别 |
| ds-cohesion | 模块化：内聚与耦合 | 七种内聚、七种耦合（由弱到强排序）；高内聚低耦合；扇入扇出 |
| ds-creational | 创建型设计模式 | 工厂方法、抽象工厂、单例、建造者、原型 |
| ds-structural | 结构型设计模式 | 适配器、桥接、组合、装饰、外观、享元、代理 |
| ds-behavioral | 行为型设计模式 | 职责链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 |
| ds-sasd | 结构化分析与设计 | 数据流图（分层、平衡原则）、数据字典、结构图；SA/SD 与 OOA/OOD 的区别 |
