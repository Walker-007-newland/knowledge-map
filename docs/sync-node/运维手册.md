## 一、节点是什么

- km-sync 是给平板之间「设备同步」做中转的服务，相当于一台「永远在线、只保管不合并」的组员。**上面只有设备端加密好的密文**，管理员和服务器都看不到学习内容。
- 管理方式：手机「团队审批」App 的「节点」页（走 8787 端口、管理密钥整包加密），或电脑浏览器 https://43.142.41.27 网页后台（走 443，用户名密码 + 可选二次验证）。两边能做的事一样，都只有元数据。
- 当前版本：**km-sync 1.3.0**（2026-10-20 随 #6 第三期、审批 App 2026.10.20.1116 上线，main 上的代码和线上一致；服务器 `.bak` 是 1.2.0）。
- 健康提醒：审批 App 后台约每 30 分钟检查一次节点，连续两次连不上、磁盘剩不到 10%、到期 ≤ 7 天、证书剩不到 48 小时时发「同步节点提醒」系统通知，每类每天最多一次。
- 知识图谱 App 的设备同步（#1 第一期，App 2026.10.19.1646）**已上线**：学生第一台平板要扫管理员发的邀请码才能建同步组，邀请码在审批 App「节点」页或网页后台生成。初始邀请码（30 天 10 次）还没用过；团队测试用的组和邀请码已清理（见第七节最后的说明）。

### 服务器上的布局
- 程序：`/opt/km-sync/km_sync_node.py`（上一版 `km_sync_node.py.bak`；systemd 单元上一版 `km-sync.service.bak`）；网页文件 `/opt/km-sync/web/`
- 配置：`/etc/km-sync/config.json`（kmsync 所有，权限 600）
- 数据：`/var/lib/km-sync/`（权限 700）
  - `node.db`：组、槽、密文。**丢了也没关系**，设备会自动重建、重传
  - `admin.db`：邀请码、组登记 / 封禁 / 备注、管理密钥的派生值、网页账号、会话、墓碑（换钥的旧组号、彻底删除的组号）、操作日志、设置（到期日、限额等）。当前表结构 4；升级表结构前会自动备份（如 `admin.db.v1.bak`、`admin.db.v3.bak`）
- 证书：`/etc/km-sync/tls/`（kmsync 所有，600）；certbot 正式证书在 `/etc/letsencrypt/live/43.142.41.27/`；验证文件目录 `/var/lib/km-sync-acme/`
- 服务：systemd `km-sync`，以系统用户 `kmsync` 运行（不是 root，只多给了绑定 80/443 的能力），挂了 1 秒内自动重启，内存上限 200M
- 系统日志：`sudo journalctl -u km-sync`（只记时间、IP、组号前 6 位、接口、状态码、字节数，不记内容）

### 本机（开发电脑）上的敏感文件
都在 `knowledge-map-app/signing/`（已 gitignore，**绝不提交、不发给别人**）：
- `sync-node.json`：节点地址、管理密钥等部署信息
- `sync-node-admin.png`：管理码二维码（审批 App 扫它连接节点，等于管理密钥）

> **1.3.0 起的变化**：管理员可以在审批 App「设置 → 同步节点 → 换管理密钥」直接换钥。节点只保留一把管理密钥，所以换钥后电脑上这两份（`sync-node.json` 里的管理密钥、`sync-node-admin.png`）**立即失效**，电脑本身不会知道。影响：`deploy.ps1` 仍能照常部署（只黄字提示）；远程测试 `test_node.py --remote` 会被拒，提示「管理密钥被拒，可能已在 App 里换过」。需要电脑上的管理码时运行 `deploy.ps1 -NewAdminKey`，手机再扫一次新的 `sync-node-admin.png`。
- `sync-node-invite.png`：初始邀请码二维码

## 三、端口与腾讯云防火墙

| 端口 | 用途 | 防火墙来源 | 状态 |
|---|---|---|---|
| TCP 22 | SSH | 默认规则 | 已放行，不要动 |
| TCP 80 | 只做两件事：Let's Encrypt 证书验证文件；其它请求 301 跳转到 https。不提供任何页面和接口 | 全部 IPv4（Let's Encrypt 从多个境外地点验证） | 已放行（默认规则） |
| TCP 443 | 网页后台（https） | 全部 IPv4 | 已放行（默认规则） |
| TCP 8787 | 平板同步（`/v1/*`）+ 审批 App 管理接口（`/admin/v1`），明文 HTTP + 应用层加密 | 全部 IPv4，备注 km-sync | 已放行（管理员 2026-10-16 添加规则） |
| 127.0.0.1:8788 | 网页后台的明文兜底口，只能经 SSH 隧道访问 | 不对外 | — |
| TCP 3389 | Windows 远程桌面，这台 Linux 用不到 | 可选：删掉这条规则 | 默认规则 |

如需在腾讯云控制台加规则：轻量应用服务器 → 选 43.142.41.27 → 防火墙 → 添加规则（应用类型：自定义；协议 TCP；端口；来源 全部 IPv4（0.0.0.0/0）；策略 允许）。

## 四、证书（Let's Encrypt IP 证书）

- 签发：2026-10-16 已用 `deploy.ps1 -SetupTls` 正式签好（签发者 Let's Encrypt，SAN 是 IP 地址 43.142.41.27，ECDSA）。不留邮箱、不开账号，管理员已同意 Let's Encrypt 服务条款。**不要重复跑 `-SetupTls`**。
- 有效期：只有约 **160 小时（6.7 天）**，必须自动续期：snap 自带的 `snap.certbot.renew.timer` 每天检查两次，`renew_before_expiry = 3 days`，所以每 3–4 天自动续一次，正常情况下证书始终剩 3 天以上。
- 续期后 `tls-deploy-hook.sh` 把证书复制到 `/etc/km-sync/tls/`，节点每 60 秒检查一次文件，自动换上，不用重启。
- 检查：`deploy.ps1 -TlsCheck`（签发者、有效期、剩余、续期定时器、`certbot renew --dry-run`）。平时看审批 App「节点 → 状态」的「证书」一行即可。
- 续期失败的影响：**只影响网页后台**（证书过期后浏览器打不开 https，HSTS 下也不能点「继续」）。审批 App（8787）和学生同步完全不受影响，SSH 隧道兜底照常可用。证书剩不到 48 小时时 App 和网页的「节点」标签出红点。
- 续期依赖 80 端口能被 Let's Encrypt 访问到，以及服务器没到期。

## 五、部署、更新与回滚

所有操作都在开发电脑上运行（经 SSH，用 `~/.ssh/km_tencent`），脚本 `knowledge-map-app/sync-node/deploy.ps1`。签名目录取 `$env:KM_SIGNING_DIR`，没设就用主目录 `knowledge-map-app\signing`。

```powershell
powershell -ExecutionPolicy Bypass -File knowledge-map-app\sync-node\deploy.ps1                 # 部署 / 更新
powershell -ExecutionPolicy Bypass -File knowledge-map-app\sync-node\deploy.ps1 -Check          # 只读体检
```

| 参数 | 作用 |
|---|---|
| （无） | 部署或更新：只换程序和网页文件，保留数据库、管理密钥、邀请码；上一版存成 `.bak`；程序没变化时不重启。如果服务器上的管理密钥已在 App 里换过（kid 和本机不一致），**照常部署**，只用黄字提示「本机 sync-node.json 和 sync-node-admin.png 已失效」，不会停下（1.3.0 起；以前会报错中断，连带卡住 `release-admin.ps1`） |
| `-Check` | 只读体检，不改任何东西：服务 active / enabled、进程身份 kmsync、对外只监听 22/80/443/8787、8788 只在 127.0.0.1、config 600、数据目录 700、证书剩 > 48 小时、https 200、80 跳转 301、hello 版本 |
| `-Rollback` | 换回上一版（连 systemd 单元一起）并重启；再部署一次即回到新版 |
| `-NewAdminKey` | 在电脑上换管理密钥（手机丢了、或 App 里换过钥后电脑要重新拿到管理码时用）：旧管理码立即失效，重新生成 `signing/sync-node-admin.png`，审批 App 要重新扫。手机还在时，也可以直接在 App「设置 → 同步节点 → 换管理密钥」换（那样电脑上的管理码失效） |
| `-ResetAdminAccess` | 清空 IP 封禁、熔断和 IP 名单，打开外网管理，同时清空网页登录的失败计数（把自己锁在外面时用） |
| `-SetupTls` | 首次签发证书（已做过，不要重复）；`-SetupTls -StagingOnly` 只签测试证书 |
| `-TlsCheck` | 只读查看证书和续期状态 |
| `-ResetWebLogin` | 清空网页用户名、密码、二次验证和所有会话，网页登录关闭（之后在 App 里重新设密码） |

### 团队上线流程
改了节点或审批 App 的需求单，测试通过后由测试员运行 `team/release-admin.ps1 -Issue <n> -Notes "..."`：合并 main → 用工作区代码部署节点并 `-Check` → 主目录 main 快进 → 发布审批 App → 清理工作区。只改一边时加 `-SkipNode` 或 `-SkipAdmin`。它和知识图谱 App 的 `release.ps1`、文档的 `docs-commit.ps1` 共用一把排队锁，同一时间只上线一个。

### 版本一致性
#6 第三期上线（2026-10-20）后，main 上的 `km_sync_node.py` 是 1.3.0，和线上 `/v1/hello` 一致，从 main 部署不会降版本。用 `-Rollback` 回到 1.2.0 时：1.2.0 能打开表结构 4 的 admin.db，已彻底删除的组号仍拒绝重建，但 1.2.0 会在 90 天后清掉这些墓碑；回滚后记得再部署一次回到 1.3.0。

### 测试
- 本地：`python knowledge-map-app\sync-node\test_node.py`（临时目录、随机端口，跑完即删）
- 远程：先开隧道 `ssh -i ~/.ssh/km_tencent -N -L 8787:127.0.0.1:8787 ubuntu@43.142.41.27`，再 `python knowledge-map-app\sync-node\test_node.py --remote 127.0.0.1:8787`。远程测试只用备注「自动测试」的临时邀请码和组，结束时自动清理。
- **不要对真实服务器跑 NodeTest**（它故意用超前的计数测重试，会让其它客户端 10 分钟内都要靠重试；1.3.0 起它最后还会换管理密钥）。
- **不要在真实服务器上试「换管理密钥」**，除非准备好之后跑 `-NewAdminKey` 并请管理员重新扫码。

## 六、自动维护（节点自己做）

- 每 5 分钟清理：过期的信件和转交点、过期封禁、超过 90 天的操作日志、有了下一代组满 60 天的旧组、超过 90 天的换钥墓碑。「彻底删除登记」留下的墓碑是永久的，不清理。
- 操作日志只留 90 天，需要长期留存就在 App 或网页「操作日志」里定期「导出全部日志（CSV 文件）」。
- 默认限额（可在 App / 网页「限额与访问」改）：最多 30 个组、每组 50MB、单分区 4MB、单请求 8MB、每 IP 每 10 分钟 600 次。
- 管理接口防护：同一 IP 10 分钟失败 5 次封 1 小时；全部外网来源 1 小时失败 30 次熔断 1 小时；每个管理密钥 / 会话每分钟最多 120 次。来自 127.0.0.1（SSH 隧道）的请求不受这些限制。
- 节点数据**不做备份**：设备上有完整数据，node.db 丢了设备会自动重建重传；admin.db 在升级表结构时有自动备份。

## 七、故障处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 审批 App「节点」页显示「超时」/「连不上同步节点」 | 服务停了、服务器到期、8787 被防火墙挡 | `deploy.ps1 -Check`；看腾讯云控制台服务器状态和到期；确认防火墙 8787 规则 |
| App 显示「节点拒绝了请求（403）」 | 管理码失效（电脑上跑过 `-NewAdminKey`，或在另一台手机上换过钥）、当前 IP 被封、熔断、关了外网管理、IP 名单不含当前 IP | 看 `journalctl -u km-sync` 或网页后台「操作日志 → 只看安全事件」；必要时 `deploy.ps1 -ResetAdminAccess`；换过钥就在 App 重新扫码 |
| 收到「同步节点提醒」系统通知 | 连续两次连不上 / 被拒、磁盘 < 10%、到期 ≤ 7 天、证书 < 48 小时 | 按通知文字，对照本表相应一行处理；同一类每天只提醒一次 |
| 部署时出现黄字「本机 sync-node.json 和 sync-node-admin.png 已失效」 | 管理员在 App 里换过管理密钥 | 部署已照常完成，不用处理；电脑上需要管理码（远程测试等）时运行 `-NewAdminKey`，并请管理员重新扫码 |
| 远程测试提示「管理密钥被拒，可能已在 App 里换过」 | 同上 | 同上 |
| App 显示「已关闭外网管理」 | 有人在 App 里关了外网管理 | 电脑上 `deploy.ps1 -ResetAdminAccess` |
| 服务起不来 | 程序错误、配置问题 | `ssh -i ~/.ssh/km_tencent ubuntu@43.142.41.27 sudo journalctl -u km-sync -n 50`；新版本有问题就 `deploy.ps1 -Rollback` |
| 网页后台打不开 / 证书报错 | 证书没续上、80 端口不通、443 没在听 | `deploy.ps1 -TlsCheck`、`-Check`；临时用 SSH 隧道：`ssh -i ~/.ssh/km_tencent -N -L 8788:127.0.0.1:8788 ubuntu@43.142.41.27`，浏览器开 `http://localhost:8788` |
| 网页登录总说密码不对 | 失败太多封了 IP / 网页登录暂停 1 小时 | 等 1 小时，或 App 里看安全事件；App「网页登录」重新设密码；`-ResetAdminAccess` 清失败计数 |
| 手机丢了 | 管理码在手机里 | 电脑 `deploy.ps1 -NewAdminKey`，新手机扫新的 `sync-node-admin.png`；网页后台也去 App 里「全部踢下线」并重设密码（或 `-ResetWebLogin`） |
| 出现不认识的同步组 | 邀请码外泄 | App / 网页「同步组」→「移除并封禁」，再到「邀请码」作废它用的那张 |
| 日志里有陌生 IP 的 GET 请求返回 405 | 国内线路设备对看到的明文 URL 回访（10-16 已查明），不是攻击 | 无需处理；签名接口无法这样调用 |
| 服务器被攻破（怀疑） | — | 读不到学习内容（端到端加密）。重装后重新部署、`-NewAdminKey`、作废所有旧邀请码 |
| 磁盘快满（剩 < 10%，标签红点） | 组数据过多 | 「同步组」里清空或移除不用的组；调低每组空间上限 |
| 学生说「已被移出」「不在同步组里了」「同步组已过期」 | 另一台设备移除了它；或它超过 60 天没同步 | 设备端问题，节点不用处理：让学生在已同步的那台上「添加设备」，这台退出同步组后扫加入码重新加入 |
| 学生说「邀请码已失效」 | 管理员作废了建组用的那张邀请码，组被删后无法重建 | 发一张新邀请码，学生在同步页「其它 → 重新扫邀请码」 |

**「同步组」列表里的 6 条已封禁空组**（2026-10-19）：#1 测试后留下 6 条「已移除并封禁」的组登记，都没有数据，不影响使用。1.3.0 起可以清理：审批 App 或网页后台「同步组」→ 点开灰色的已封禁空组 →「彻底删除登记」（不能撤销，组号永久封禁）。开发和测试都没有替管理员删，截至 2026-10-20 上线时还在。
